The Stale Feed is the data behind the leaderboard in one stable, documented JSON format. It's meant for anti-fraud and bot-detection teams who want to check traffic against what current Chrome really sends, automatically, instead of reading a web page.

Files: schema-v1.json (JSON Schema, draft 2020-12) · sample-v1.json (sample payload, regenerated from the current capture every time the site updates).

Quick start

The sample is public, so you can try it now:

curl -s https://stalefp.github.io/feed/sample-v1.json \
  | jq -r '.platforms[] | select(.status == "captured")
           | [.platform, .version, .variants.default.ja4, .variants.default.quic_ja4] | @tsv'

Every JA4 that real, current Chrome sends, across platforms and variants:

import json, urllib.request
feed = json.load(urllib.request.urlopen("https://stalefp.github.io/feed/sample-v1.json"))
assert feed["schema"] == "stale-feed/v1"
chrome_ja4 = {v[k] for p in feed["platforms"].values() if p["status"] == "captured"
              for v in p["variants"].values() if v for k in ("ja4", "ja4_resumed", "quic_ja4") if v[k]}

A JA4 in this set is consistent with current Chrome; one that isn't, from a client claiming to be current Chrome, is worth a closer look. The library results below tell you which tools can produce which of these.

Format

One JSON object. Times are UTC ISO 8601 (2026-10-02T05:38:28Z); dates are the UTC date of the capture. TLS values follow JA4 conventions (GREASE removed). A value we didn't measure is null, never guessed.

FieldTypeMeaning
schemastringAlways "stale-feed/v1" for this version. Check it before parsing.
generated_atdate-timeNewest source timestamp in the payload (capture or leaderboard run).
samplebooleantrue in the public sample.
variant_definitionsobjectHow each Chrome variant (default, no_ca34, pq) was captured: flags, and population share where Chrome's variations seed states one.
platformsobjectlinux, windows, macos: Chrome version, capture time and the fingerprints of each variant. See below.
changesarrayWhat changed between consecutive captures, newest first.
historyarrayPast captures with their main fingerprints, newest first.
libraries_compared_againstobjectWhich Chrome capture the library results are scored against (Linux).
librariesarrayOne entry per library profile tested: verdict, per-variant match results, HTTP/2 and HTTP/3 results.

Fingerprints per platform

platforms.<os> has status (captured or not_captured), and when captured: browser, channel, version, os, captured_at, captured_date, capture_run (the GitHub Actions run), stable_newest and stable_full_rollout (from Google's VersionHistory API at capture time), and variants.

Chrome doesn't send one fingerprint. Each platform has three real captures:

  • default: branded Chrome, fresh profile, no flags. Includes the trust-anchors extension (ca34). What most users send.
  • no_ca34: Chrome with --disable-features=TLSTrustAnchorIDs, the less common variant without ca34.
  • pq: Chrome forced into Google's post-quantum experiment group, which adds extension 0x12e0.
Variant fieldExampleMeaning
ja4…TLS JA4, fresh connection.
ja4_resumed…TLS JA4 of a resumed connection (with pre_shared_key).
ja4_rstringRaw JA4 (full cipher, extension and signature algorithm lists).
quic_ja4, quic_ja4_resumed…JA4 of the TLS handshake inside QUIC (HTTP/3).
h2_akamai…HTTP/2 fingerprint, Akamai format: SETTINGS | WINDOW_UPDATE | PRIORITY | pseudo-header order.
h3_settings…HTTP/3 SETTINGS, {id: value}, GREASE removed.
has_trust_anchorsbooleanWhether the capture sent ca34.
configstringName of the capture configuration it came from.

HTTP/3 values come from Chrome forced onto HTTP/3 against our own local capture server, not a live public site, so a real site's setup could change some HTTP/3 details.

Changes and history

changes has one entry per pair of consecutive captures, newest first: platform, date, previous and current ({version, captured_at}), and fields, a list of {field, variant, label, before, after}. An empty fields list means Chrome was recaptured and nothing we compare changed.

Compared fields: chrome_version; per variant ja4, ja4_resumed, quic_ja4, quic_ja4_resumed, h2_akamai, h3_settings, has_trust_anchors, extensions, sig_algs, groups, ciphers, quic_transport_params; for the default variant key_shares and alps; and pq_population_share.

history lists archived captures plus the current one, each with the ja4, ja4_resumed, quic_ja4 and h2_akamai of every variant. A capture is archived when the Chrome version or a fingerprint field changed.

Today the change log and history cover Linux, starting with the capture of Sep 27, 2026. Windows and macOS captures started on Oct 2, 2026; their past captures aren't archived yet, so for those platforms the feed has the current capture only.

Library results

Each entry in libraries is one library profile (for example curl_cffi chrome150), tested by making real requests and comparing what it sends against the Linux capture, field by field. The same data drives the leaderboard.

FieldMeaning
id, library, maintainer, language, library_version, profileWhat was tested. id is stable across runs.
verdictexact, exact_variant, close, behind or not_tested, against Chrome's default variant. matched_variant says which variant an exact_variant matches.
counted_mismatchesCounted fields that differ from the default variant (ciphers, extensions, signature algorithms, groups, key shares, ALPS, certificate compression, HTTP/2).
variants.<id>Per Chrome variant: ja4_match, ja4_resumed_match, quic_ja4_match, fields_exact, counted_mismatches.
http2_match, http3HTTP/2 match, and HTTP/3 status (tested, no_support, not_tested, failed) with summary, quic_ja4 and h3_settings_match.
fingerprintWhat the library actually sent: ja4, ja4_resumed, h2_akamai, quic_ja4. Useful as a deny or watch list.
versions_behind, profile_chrome_major, tested_at, resumption, missingHow far behind the profile is, when it was tested, whether it resumes sessions, and what it lacks compared with Chrome.

Versioning

  • The schema field names the format. Within stale-feed/v1, fields are only added (as optional), never renamed, removed or given a different type.
  • Ignore fields you don't recognize; that's how new data reaches you without breaking anything.
  • A breaking change would ship as stale-feed/v2 with its own schema file, and v1 stays available while you switch.
  • The public files the site reads (data/latest.json, data/libraries.json, data/platforms.json) are the site's internal layout and can change at any time. Build on the feed format, not on those.
